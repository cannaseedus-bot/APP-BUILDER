📖 ASX Overview

The ASX Philosophy

Atomic ASX is a JSON-first framework where:

  • Every app/game = ONE .asx or .asxtape JSON file
  • ASX Engine = Universal interpreter
  • No frameworks (React/Vue/etc) - pure vanilla JS
  • No build step - instant deployment
  • Tiny file sizes (~KB not MB)

The Holotape Metaphor

Think of ASX like cassette tapes:

  • .asx file = The tape 🎵
  • ASX Engine = The player 📻
  • Result = Your app 🎮

One engine, infinite tapes!

🎵 .asxtape Format (Legacy)

This is the older format. Still works, but .asx shell format is preferred for new apps. 
{
  "holotape": {
    "id": "my_game",
    "title": "My Game",
    "genre": "RPG",
    "blocks": ["BG-Default", "HUD-Combat", "Grid-Game"],
    "data": {
      "units": "/data/units.json",
      "maps": "/data/maps.json"
    }
  }
}

Use .asxtape for:

  • Simple holotape-style apps
  • Content-heavy games
  • Legacy compatibility

⭐ .asx Shell Format (MODERN)

THIS IS YOUR PRIMARY FORMAT! The .asx shell format is what you'll generate 99% of the time.

Complete .asx Structure

{
  "$schema": "asx-shell-v1",
  "$version": "1.0.0",
  
  "$metadata": {
    "name": "My App",
    "description": "What this app does",
    "author": "Creator name",
    "version": "1.0.0"
  },
  
  "$state": {
    // All application data lives here
    "user": { "name": "", "score": 0 },
    "ui": { "theme": "dark", "menuOpen": false }
  },
  
  "$computed": {
    // Derived values (calculated from state)
    "userLevel": "Math.floor(get('user.score') / 100)",
    "isLoggedIn": "get('user.name').length > 0"
  },
  
  "$effects": [
    // Reactive triggers (when state changes, do something)
    {
      "when": "user.score",
      "run": {
        "op": "if",
        "test": { "gte": [{ "$get": "user.score" }, 100] },
        "then": [{ "op": "notify", "message": "Level up!" }]
      }
    }
  ],
  
  "$routes": {
    // Different "pages" or "screens"
    "home": { "component": "HomePage" },
    "game": { "component": "GameScreen" }
  },
  
  "$components": {
    // Reusable UI building blocks
    "HomePage": { /* UI definition */ },
    "GameScreen": { /* UI definition */ }
  },
  
  "$modals": {
    // Popup dialogs
    "settings": { /* modal definition */ }
  },
  
  "$keyboard": {
    // Keyboard shortcuts
    "Escape": { "op": "openModal", "name": "settings" }
  },
  
  "$styles": {
    // CSS-in-JSON
    ".my-class": { "color": "#00ff99" }
  },
  
  "$data": {
    // Static content or configuration
    "levels": [...],
    "enemies": [...]
  }
}
Key Insight: Everything is declarative. You describe WHAT you want, not HOW to implement it. The ASX Engine handles the HOW.

💾 State Management

The $state Section

This is your application's single source of truth. ALL data goes here.

"$state": {
  "player": {
    "name": "Hero",
    "health": 100,
    "maxHealth": 100,
    "level": 1,
    "xp": 0,
    "inventory": []
  },
  "game": {
    "scene": "town",
    "paused": false,
    "enemies": []
  },
  "ui": {
    "menuOpen": false,
    "selectedItem": null,
    "notifications": []
  }
}

Best Practices:

  • ✅ Organize by domain (player, game, ui)
  • ✅ Use descriptive names
  • ✅ Initialize with sensible defaults
  • ✅ Keep it flat when possible

The $computed Section

Computed values are automatically calculated from state. They update reactively.

"$computed": {
  // Simple calculations
  "healthPercent": "get('player.health') / get('player.maxHealth') * 100",
  
  // Comparisons
  "isAlive": "get('player.health') > 0",
  "isLowHealth": "get('player.health') < 20",
  
  // Array operations
  "inventoryCount": "get('player.inventory').length",
  "hasItems": "get('player.inventory').length > 0",
  
  // Complex logic
  "playerLevel": "Math.floor(get('player.xp') / 100) + 1",
  "nextLevelXP": "(Math.floor(get('player.xp') / 100) + 1) * 100"
}
Computed values are read-only. They recalculate automatically when their dependencies change. Access them in UI with {{computed.healthPercent}}

Component Structure

Components are UI building blocks. Everything is nested JSON objects.

Available Component Types:

Type Purpose Key Props

🛣️ Routing System

Defining Routes

Routes are different "screens" or "pages" in your app.

"$routes": {
  "menu": {
    "component": "MainMenu",
    "sections": [
      {
        "panel": {
          "title": "Main Menu",
          "children": [
            {
              "button": {
                "label": "Start Game",
                "variant": "primary",
                "onClick": { "op": "setRoute", "route": "game" }
              }
            },
            {
              "button": {
                "label": "Settings",
                "variant": "secondary",
                "onClick": { "op": "openModal", "name": "settings" }
              }
            }
          ]
        }
      }
    ]
  },
  
  "game": {
    "component": "GameScreen",
    "sections": [
      { "canvas3d": { "scene": "level1", "controller": "fps" } },
      { "component": "GameHUD" }
    ]
  },
  
  "inventory": {
    "component": "InventoryScreen",
    "sections": [
      { "component": "ItemList" },
      { "component": "ItemStats" }
    ]
  }
}

Navigation Between Routes:

{
  "op": "setRoute",
  "route": "game"
}

⚡ Effects System

Effects are reactive triggers. When state changes, effects run automatically.

Effect Structure

"$effects": [
  {
    "when": "player.health",  // Watch this state path
    "run": {                   // Do this when it changes
      "op": "if",
      "test": { "lte": [{ "$get": "player.health" }, 0] },
      "then": [
        { "op": "set", "path": "game.gameOver", "value": true },
        { "op": "notify", "message": "You died!" },
        { "op": "setRoute", "route": "gameover" }
      ]
    }
  }
]

Common Effect Patterns

1. Health Warning

{
  "when": "player.health",
  "run": {
    "op": "if",
    "test": { "lt": [{ "$get": "player.health" }, 20] },
    "then": [
      { "op": "notify", "message": "⚠️ Low health!" }
    ]
  }
}

2. Level Up

{
  "when": "player.xp",
  "run": {
    "op": "if",
    "test": { "gte": [{ "$get": "player.xp" }, { "$get": "computed.nextLevelXP" }] },
    "then": [
      { "op": "updateBy", "path": "player.level", "by": 1 },
      { "op": "notify", "message": "🎉 Level up!" }
    ]
  }
}

3. Auto-save

{
  "when": "*",  // Watch all state changes
  "run": {
    "op": "fetch",
    "url": "/api/save",
    "method": "POST",
    "body": "{{$state}}"
  }
}

Available Operations

Operation Purpose Example
set Set state value { "op": "set", "path": "user.name", "value": "Hero" }
assign Merge object { "op": "assign", "path": "user", "value": {...} }
updateBy Increment/decrement { "op": "updateBy", "path": "score", "by": 10 }
push Add to array { "op": "push", "path": "inventory", "value": {...} }
removeAt Remove from array { "op": "removeAt", "path": "inventory", "index": 0 }
toggle Flip boolean { "op": "toggle", "path": "ui.menuOpen" }
notify Show notification { "op": "notify", "message": "Hello!" }
setRoute Navigate { "op": "setRoute", "route": "game" }
openModal Show modal { "op": "openModal", "name": "settings" }
closeModal Hide modal { "op": "closeModal" }
sequence Run multiple ops { "op": "sequence", "steps": [...] }
if Conditional { "op": "if", "test": {...}, "then": [...], "else": [...] }

✨ Best Practices for Mx2LM

DO:

  • ✅ Always include $schema and $metadata
  • ✅ Initialize state with sensible defaults
  • ✅ Use computed values for derived data
  • ✅ Keep components small and focused
  • ✅ Use effects for reactive behaviors
  • ✅ Provide keyboard shortcuts
  • ✅ Test JSON validity before outputting
  • ✅ Use descriptive names
  • ✅ Comment complex logic in metadata

DON'T:

  • ❌ Generate invalid JSON (no trailing commas, no comments in JSON)
  • ❌ Use undefined state paths
  • ❌ Forget to initialize state
  • ❌ Mix imperative code in declarative config
  • ❌ Create circular dependencies in computed values
  • ❌ Overcomplicate - keep it simple
Remember: Your job is to generate perfect, working JSON. When a user says "make me a todo app", you output a complete .asx file that works immediately. No placeholders. No "implement this later". Complete apps.

Problem Solution
