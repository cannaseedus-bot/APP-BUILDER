1. Mental Model
Atomic HTML for ASX is:
  • HTML as the canvas
  • Atomic CSS tokens on attributes
  • ASX Blocks as JSON payloads
  • XCFE-style blocks for @if / @then / @else
  • A tiny runtime that binds everything
2. Atomic CSS Tokens
Use attributes instead of class chains.
Token Meaning
[x]Atomic element baseline
[xt]Atomic inline text
[row], [col]Flex row / column
[panel], [panel-soft]Card surfaces
[pad="N"]Pad using scale (1–5)
[gap="N"]Flex gap scale
[h1], [h2], [h3]Heading styles

[btn], [btn-accent]Interactive buttons
3. ASX Block Shape
{ "type": "asx-block", "id": "block:player-card", "component": "PlayerCard", "encrypted": false, "props": { ... } }
Rule: Every ASX Block is a self-contained JSON record. The runtime decides how to render each component using its props.
4. XCFE Block Shape
{ "@if": "props.balance > 0", "@then": { "type": "asx-block", "component": "TokenBalance", "props": { "balance": 2840 } }, "@else": { "type": "asx-block", "component": "EmptyState", "props": { "label": "No balance yet", "hint": "Connect a wallet to begin." } } }
XCFE-lite: V4 lets you drive UI branching directly from JSON using @if / @then / @else blocks. Conditions see a tiny context object (props, env) and pick the correct branch.
Section 1 · Atomic HTML Primer
Atomic HTML keeps the page minimal: everything you see is the combination of three layers:
  1. Atomic CSS — small, named tokens defined as attributes.
  2. Semantic HTML — your document structure, no framework.
  3. ASX Blocks — JSON packets carrying UI state and logic hints.
  4. XCFE Blocks — JSON packets that decide which blocks to render.
1.1 Base Atomic Pattern
You mark any element as "atomic" by adding [x]. From there you apply tokens: [row], [panel], [h1], etc.
<div x panel row gap="3"> <div col gap="2"> <div h1>ASX Atomic HTML</div> <div lead> Single-file OS-style layout using pure HTML, CSS variables, and ASX JSON blocks. </div> </div> <button x btn btn-accent>Do Something</button> </div>
Atomic tokens are just attributes. No class names necessary.
Design discipline: resist the urge to invent ad-hoc CSS. If something feels reusable, encode it as a new Atomic token and reuse that instead of custom styles.

Section 3 · ASX Blocks Language
ASX Blocks are JSON objects that describe UI components and their data. The runtime interprets these blocks and renders them using Atomic HTML.
3.1 Block Structure
{ "type": "asx-block", "id": "block:user-profile:abc123", "component": "UserProfile", "encrypted": false, "signature": "asx-sha256-...", "props": { "user": { "name": "Sarah Chen", "role": "Developer", "avatar": "/avatars/sarah.jpg" }, "stats": { "projects": 12, "tokens": 4500 } }, "layout": { "gridArea": "sidebar", "priority": 2 } }
3.2 Component Registry
The runtime maintains a registry of components that know how to render different block types:
// Component registry ASX.Components = { UserProfile: (props) => ` <div x panel col gap="2"> <div row align-center gap="2"> <img src="${props.user.avatar}" width="40" height="40" style="border-radius: 50%;"> <div col> <div style="font-weight: 600;">${props.user.name}</div> <div lead>${props.user.role}</div> </div> </div> <div row spread> <div>Projects: ${props.stats.projects}</div> <div>Tokens: ${props.stats.tokens}</div> </div> </div> `, TokenBalance: (props) => ` <div x panel-accent center gap="2"> <div h2>Token Balance</div> <div style="font-size: 24px; font-weight: 700;"> ${props.balance} ASX </div> </div> ` };
3.3 XCFE-style Control Blocks (@if / @then / @else)
Instead of branching in JavaScript, you can describe conditional UI directly in JSON. ASX V4 adds XCFE-lite support for @if / @then / @else:
{ "@if": "props.balance >= 1", "@then": { "type": "asx-block", "component": "TokenBalance", "props": { "balance": 2840 } }, "@else": { "type": "asx-block", "component": "EmptyState", "props": { "label": "No balance yet", "hint": "Earn or deposit ASX tokens." } } }
How it works: the runtime flattens the block list: every node with @if picks either @then or @else, and only the chosen branch is rendered. Branches can be single blocks or arrays of blocks, and they can nest other @if nodes.

Section 5 · ASX Block Runtime + XCFE-lite
The complete ASX Block runtime in vanilla JavaScript, upgraded for XCFE-style @if / @then / @else control flow.
// ASX Block Runtime V4 (XCFE-lite) window.ASX = { Components: {}, env: {}, registerComponent(name, renderFn) { this.Components[name] = renderFn; }, // Evaluate @if expressions against a tiny context evalCondition(expr, ctx) { try { /* XCFE-lite: expression sees props/env via "ctx" */ const fn = new Function("ctx", "with(ctx){ return !!(" + expr + "); }"); return !!fn(ctx); } catch (e) { console.warn("XCFE condition error:", e); return false; } }, // Flatten XCFE blocks (@if/@then/@else) to plain ASX blocks processNode(node) { if (!node) return []; // Arrays: process each child if (Array.isArray(node)) { return node.flatMap(n => this.processNode(n)); } // Control-flow node if (typeof node === "object" && "@if" in node) { const expr = node["@if"]; const ctx = { props: node.props || {}, env: this.env || {} }; const passed = this.evalCondition(expr, ctx); const branch = passed ? node["@then"] : node["@else"]; if (!branch) return []; return this.processNode(branch); } // Plain ASX block if (typeof node === "object" && node.component) { return [node]; } return []; }, renderBlock(block) { const component = this.Components[block.component]; if (!component) { return `<div style="color: var(--danger);"> Unknown component: ${block.component} </div>`; } try { return component(block.props || {}); } catch (error) { return `<div style="color: var(--danger);"> Render error: ${error.message} </div>`; } }, renderBlocks(blocks, containerId) { const container = document.getElementById(containerId); if (!container) return; const flat = this.processNode(blocks || []); const html = flat.map(block => this.renderBlock(block)).join(""); container.innerHTML = html; }, init() { console.log("🧩 ASX Block Runtime V4 (XCFE-lite) ready"); } }; // Auto-initialize ASX.init();
Production pattern: you can swap out evalCondition for a stricter XCFE evaluator (no new Function), but the block shapes (@if/@then/@else) stay the same. The UI remains 100% JSON-driven.
