XJSON v1 Specification & OS Manual
PRIME Edition — Universal AST Language (v2 with Control Flow / XCFE)

XJSON is a universal AST-JSON language capable of representing any: HTML, CSS, Logic (JS/PY/PHP), state, routing, components, templates, SCX blocks, compression, agents, and OS-level layout.

It is the core language of ASX, SCX, PRIME OS, Micronaut AI, and all holotape-based runtimes. The v2 PRIME edition adds an official control-flow model (@if, @then, @else) powered by the XJSON Control Flow Engine (XCFE).

1. Introduction

XJSON is a universal Abstract Syntax Tree model, serialized entirely as JSON. It is designed to serve simultaneously as:

  • A UI language
  • A CSS/SCX styling system
  • A logic representation (multi-language)
  • A state machine / database layer
  • A routing system
  • A component/template engine
  • An agent instruction format
  • A compression-friendly symbolic code layer
  • A tape OS packaging format

Everything is a node — and every node is declarative and combinable. Control flow and branching are expressed as data using the @if family of blocks, not as raw code.

2. Language Overview

Every XJSON document begins with:

{ "xjson": "1.0", "nodes": [] }

Nodes can represent:

  • HTML structures
  • CSS styles
  • JS/Python/PHP logic
  • Components
  • State
  • Tapes
  • Agents
  • SCX blocks
  • Control flow (@if/@then/@else)
3. Node Types

The primary node types include:

  • element — HTML/UI tree
  • style — CSS/SCX rule
  • logic — multi-language logic
  • control — control-flow nodes (@if/@then/@else)
  • component
  • route
  • state
  • agent
  • tape
  • flashram

The control node type maps to the @if block family and is executed by the XJSON Control Flow Engine.

4. Element Nodes (HTML)

Example:

{ "type": "element", "tag": "div", "props": { "scx": "⟁F ⟁Acenter" }, "children": [ { "type": "text", "value": "Hello PRIME" } ] }
5. Styles / SCX Atomic CSS

XJSON supports raw CSS and symbolic SCX.

{ "type": "style", "selector": "[scx~='⟁BTN']", "rules": { "padding": "8px 12px", "border-radius": "12px", "background": "linear-gradient(...)" } }

SCX block example:

⟁BTN = { "border": "1px solid rgba(22,242,170,0.4)", "padding": "6px 12px", "font-size": "12px" }
6. Logic Engine (JS/PY/PHP)

XJSON logic is AST-safe, multi-language, and can be combined with data-driven control-flow blocks defined in the next section.

{ "type": "logic", "lang": "js", "name": "increment", "code": [ "PrimeOS.state.score += 1;", "render();" ] }

Python:

{ "type": "logic", "lang": "py", "code": ["state['score'] += 1"] }

PHP:

{ "type": "logic", "lang": "php", "code": ["$score = $score + 1;"] }

Logic blocks should avoid arbitrary eval() in favor of structured data and XCFE-driven branching.

6.5 Control Flow Blocks (@if / @then / @else)

Control flow in XJSON is not free-form code — it is expressed as data blocks interpreted by the XJSON Control Flow Engine (XCFE).

Block Shape
{ "@if": { "cond": { "left": <value|var|ref>, "op": "<operator>", "right": <value|var|ref> }, "@then": [ /* array of normal ASX / XJSON blocks */ ], "@else": [ /* optional fallback blocks */ ] } }

left and right can be literals or references like "$player.hp", which are resolved against the current tape / OS context (state, session, HUD, agent memory).

Supported Operators
Equality: ==, != Comparison: >, <, >=, <= String: contains, startswith, endswith Set: in, not_in Nullability: isnull, notnull Existence: isset, notset Boolean: and, or, not Type: is_string, is_number, is_boolean, is_array, is_object Agent-based: agent_eval, agent_score

Agent-based operators allow delegation to micro-agents (Mx2LM, Mx2Qwen, Mx2PHP, etc.) for higher-level decisions.

Example — Simple HP Check
{ "@if": { "cond": { "left": "$player.hp", "op": ">", "right": 0 }, "@then": [ { "@block": "show_status", "value": "Player is alive" } ], "@else": [ { "@block": "game_over", "value": "You died" } ] } }
Example — ASX RISK Attack
{ "@if": { "cond": { "left": "$attack.roll", "op": ">", "right": "$defense.roll" }, "@then": [ { "@log": "Attacker wins" }, { "@territory/transfer": { "from": "$defender", "to": "$attacker" }} ], "@else": [ { "@log": "Defender survives" }, { "@army/loss": { "faction": "$attacker", "amount": 1 }} ] } }
Example — PRIME OS HUD Switch
{ "@if": { "cond": { "left": "$os.mode", "op": "==", "right": "combat" }, "@then": [ { "@hud/open": "combat_panel" } ], "@else": [ { "@hud/open": "dashboard" } ] } }
XCFE Runtime Contract

XCFE runs inside ASX SERVER PRIME as: window.XJSONEngine.executeIfBlock(block, ctx). It:

  • Resolves variables (e.g. $player.hp).
  • Evaluates the condition via the operator table.
  • Executes @then or @else arrays by delegating to ASXRuntime.executeBlock().
  • Returns the updated context back to the tape / PRIME OS HUD.

This makes all control flow:

  • Deterministic
  • Serializable and tape-safe
  • Agent-trainable (logs can be replayed)
  • Safe to run offline / local-first
7. Component Model

Components are reusable UI templates:

{ "type": "component", "id": "card.user", "template": [ { "type": "element", "tag": "div", "props": { "scx": "⟁CARD" }, "children": [ { "type": "slot", "name": "avatar" }, { "type": "slot", "name": "name" } ] } ] }
8. Routing System
{ "type": "route", "path": "/settings", "component": "settings.panel" }

Supports: redirects, nested routes, tape-to-tape routing.

9. State System (XState Mode)
{ "type": "state", "id": "prime.user", "value": { "score": 100, "theme": "dark" } }

State values are directly consumable by control-flow blocks via variable references (e.g. $prime.user.score).

10. Agent System (MX2)

Agents include MX2LM (coordinator), Mx2Qwen, Mx2Cline, Janus, etc.

{ "type": "agent", "id": "mx2lm", "role": "coordinator", "skills": ["routing", "logic", "intent"], "endpoints": { "infer": "/api/mx2lm/infer", "train": "/api/mx2lm/train" } }

Agents can be consulted via agent_eval / agent_score operators in control blocks to delegate higher-level decisions.

11. Tapes / Holotapes

Each tape is a mini-server. Capable of:

  • Running UI
  • Running logic
  • Hosting agents
  • Calling ASX SERVER REST points
  • Connecting to tunnels
  • Booting standalone
  • Being merged into any larger OS
{ "type": "tape", "id": "prime-os", "entry": "index.xjson", "agents": ["mx2lm", "mx2qwen"], "public": "./public/" }
12. Flash-RAM Snapshots

Instant resume system:

{ "type": "flashram", "snapshot": { "theme": "grid", "score": 120 } }
13. Atomic ASX Blocks

Blocks define entire UI structures using only symbols.

⟁PAGE → <html><head></head><body></body></html> ⟁CARD → <div class="card"></div> ⟁BTN → <button class="atomic-btn"></button> ⟁TABLE → <table></table> ⟁FORM → <form></form> ⟁DIV → <div></div>

You can build entire apps with symbols.

14. SCX Compression System

SCX replaces repeated or long HTML/CSS/Logic patterns with symbolic nouns.

⟁F = display:flex ⟁Fcol = flex-direction:column ⟁Psm = padding:6px ⟁R2 = border-radius:8px ⟁BGgrad = background:linear-gradient(...)
15. Code → AST → XJSON Transformation Engine

Any code in any language becomes AST → XJSON.

HTML:

<h1>Hi</h1>

→ XJSON:

{ "type": "element", "tag": "h1", "children": ["Hi"] }

CSS:

h1 { color:red }

→ XJSON:

{ "type": "style", "selector": "h1", "rules": { "color": "red" } }

Logic:

score += 1

→ XJSON Logic:

{ "type": "logic", "lang": "js", "code": ["score++"] }

  • Symbols only map to whitelisted blocks
  • Control flow is declarative, not arbitrary code

18. XJSON Builder / SCX Generator Engine

This engine can build any UI, any tape, any OS.

Input (XJSON):

{ "type": "tape", "id": "demo", "ui": [{ "type": "element", "tag": "div" }] }

Output:

  • index.html
  • ui.xjson
  • style.xjson
  • logic.xjson
  • runtime.js (with XCFE embedded)
  • agents/ folder
  • flashram/ folder
  • Ready-to-run mini server

Core idea:
Every tape is a server. Every tape is a runtime. Every tape can auto-discover others via REST broadcasting.
