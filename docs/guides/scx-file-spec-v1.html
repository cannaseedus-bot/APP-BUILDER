0. Overview & Design Goals

XJSON is a universal, AST-shaped JSON language designed to encode HTML, CSS, JavaScript, Python, PHP, and higher-level OS concepts (tapes, agents, state, routing) into a single, compressible, language-neutral format.

Instead of shipping raw code plus templates plus styles plus configuration, XJSON ships a single, structured representation that:

  • Can be interpreted by MX2PHP / MX2PY / MX2JS.
  • Can be compressed by SCX and expanded at runtime.
  • Can describe a full OS HUD, including PRIME cockpit, Basher terminal, and agent grid.
  • Can be snapshotted and restored via Flash-RAM.
Think of XJSON as the “HTML+CSS+JS+Config+Agents+State” of your OS, but expressed as one, unified AST that any runtime can read. Blocks are your superpower: a whole page can be controlled via a single symbol.
1. Data Model

At its core, an XJSON document is a tree of nodes. Each node has: 

{
  "type": "element|style|logic|component|route|state|agent|tape|flashram",
  "id": "optional-unique-id",
  "meta": { "optional": "metadata" },
  "props": { /* type-specific properties */ },
  "children": [ /* nested nodes (for hierarchical types) */ ]
}

A typical tape.xjson serving as a full app or OS cockpit contains a top-level bundle of these node types. 

{
  "xjson": "1.0",
  "meta": {
    "id": "prime-os",
    "label": "ASX PRIME OS — GUIX HUD",
    "version": "1.0.0"
  },
  "nodes": [
    { "type": "tape",   ... },
    { "type": "route",  ... },
    { "type": "state",  ... },
    { "type": "agent",  ... },
    { "type": "style",  ... },
    { "type": "logic",  ... },
    { "type": "element", ... }
  ]
}
2. Core Node Types
2.1 Element Nodes (HTML)

Element nodes express structural HTML. They also support SCX-based block attributes to compress layout and styling decisions. 

{
  "type": "element",
  "tag": "div",
  "props": {
    "id": "prime-header",
    "scx": "⟁F ⟁Fbetween ⟁Acenter ⟁MBSM"
  },
  "children": [
    { "type": "text", "value": "ASX PRIME OS — XJSON Manual" }
  ]
}
2.2 Style Nodes (CSS)

Style nodes define atomic SCX tokens and direct CSS selectors. Runtimes can either generate CSS text or keep it in data form for further transformation. 

{
  "type": "style",
  "id": "core.scx",
  "tokens": {
    "⟁F": { "display": "flex" },
    "⟁Fcol": { "flex-direction": "column" },
    "⟁PANEL": {
      "background": "var(--panel)",
      "border-radius": "10px",
      "border": "1px solid rgba(22,242,170,0.35)",
      "padding": "14px 16px"
    }
  },
  "raw": [
    "body[scx~='⟁BODY']{background:#020308;color:#e8fff6;font-family:system-ui,sans-serif;}"
  ]
}
2.3 Logic Nodes

Logic nodes are AST-safe behavior descriptions. They can store JavaScript, Python, PHP, or SCX-logic instructions and are invoked by events or agent pipelines. 

{
  "type": "logic",
  "id": "prime.incrementScore",
  "lang": "js",
  "trigger": {
    "event": "click",
    "selector": "#btnStateInc"
  },
  "actions": [
    { "kind": "state.increment", "path": "user.score", "value": 5 },
    { "kind": "render.stateView" }
  ]
}
3. SCX Atomic Blocks & Whole-Page Blocks

SCX is the symbolic compression layer. It lets you describe entire structures — from a single button to a full page frame — using short codes.

3.1 Basic Block Vocabulary
BlockHTML / Responsibility
⟁HTMLRoot <html> container
⟁HEAD<head> meta, title, links
⟁BODYTop-level <body> frame
⟁HEADERPage header region (brand, nav)
⟁MAINMain content layout grid
⟁FOOTERFooter / status bar area
⟁CARDGeneric panel/card wrapper
⟁BTNAction button template
⟁FORMStructured form layout
⟁TABLETable styling block
3.2 Defining Page Blocks (SCX → HTML)

You can define a whole-page layout using SCX blocks, then reuse this “super block” for any app. 

{
  "type": "style",
  "id": "page.blocks",
  "tokens": {
    "⟁HTML": { "height": "100%", "width": "100%" },
    "⟁BODY": {
      "min-height": "100vh",
      "margin": "0",
      "background": "radial-gradient(circle at top, #08101e, #020308 55%)",
      "color": "var(--text)",
      "font-family": "system-ui,sans-serif"
    },
    "⟁HEADER": {
      "display": "flex",
      "justify-content": "space-between",
      "align-items": "center",
      "padding": "10px 16px",
      "border-bottom": "1px solid rgba(22,242,170,0.35)"
    },
    "⟁MAIN": {
      "display": "grid",
      "grid-template-columns": "260px 1fr",
      "gap": "12px",
      "padding": "12px 16px"
    },
    "⟁FOOTER": {
      "padding": "8px 16px",
      "border-top": "1px solid rgba(22,242,170,0.35)",
      "font-size": "11px",
      "color": "var(--muted)"
    }
  }
}
3.3 Using Blocks to Render a Whole Page

A full page can be described in XJSON using only blocks — you choose the symbols; the runtime expands them. 

{
  "type": "element",
  "tag": "html",
  "props": { "scx": "⟁HTML" },
  "children": [
    {
      "type": "element",
      "tag": "head",
      "props": { "scx": "⟁HEAD" },
      "children": [
        { "type": "element", "tag": "title",
          "children": [ { "type": "text", "value": "XJSON Page using SCX Blocks" } ]
        }
      ]
    },
    {
      "type": "element",
      "tag": "body",
      "props": { "scx": "⟁BODY" },
      "children": [
        {
          "type": "element",
          "tag": "header",
          "props": { "scx": "⟁HEADER" },
          "children": [
            { "type": "element", "tag": "div",
              "children": [ { "type": "text", "value": "ASX PRIME · XJSON" } ] },
            { "type": "element", "tag": "nav",
              "children": [ { "type": "text", "value": "Docs · API · Spec" } ] }
          ]
        },
        {
          "type": "element",
          "tag": "main",
          "props": { "scx": "⟁MAIN" },
          "children": [
            {
              "type": "element",
              "tag": "aside",
              "props": { "scx": "⟁CARD" },
              "children": [
                { "type": "text", "value": "Sidebar / TOC" }
              ]
            },
            {
              "type": "element",
              "tag": "section",
              "props": { "scx": "⟁CARD" },
              "children": [
                { "type": "text", "value": "Main content panel" }
              ]
            }
          ]
        },
        {
          "type": "element",
          "tag": "footer",
          "props": { "scx": "⟁FOOTER" },
          "children": [
            { "type": "text", "value": "XJSON v1 · SCX Blocks · PRIME Atomic CSS" }
          ]
        }
      ]
    }
  ]
}
3.4 Blocks as Superpowers

By defining normal HTML primitives (<html>, <body>, <header>, <main>, <footer>, <div>, <ul>, <form>, etc.) as SCX blocks, you can:

  • Switch entire themes by swapping one SCX token pack.
  • Apply responsive behavior through block-level media rules.
  • Ship a “page skeleton” CDN and feed project-specific variables via XJSON.
4. Style Schema (CSS via XJSON)

XJSON style nodes can be:

  • Token-based (SCX atoms).
  • Raw CSS fragments for direct insertion.
  • Block packs loaded from CDNs.
{
  "type": "style",
  "id": "prime.atomic",
  "tokens": {
    "⟁BTN": {
      "border-radius": "999px",
      "border": "1px solid rgba(22,242,170,0.4)",
      "padding": "4px 10px",
      "background": "linear-gradient(135deg, rgba(0,0,0,0.75), rgba(0,40,30,0.95))",
      "color": "var(--text)"
    },
    "⟁BTNpri": {
      "background": "linear-gradient(135deg,#16f2aa,#00ffff)",
      "color": "#000",
      "border-color": "#00ffff"
    }
  }
}
5. Logic & Event Model

Logic nodes map events to actions (state mutations, agent calls, navigation). 

{
  "type": "logic",
  "id": "basher.run",
  "lang": "js",
  "trigger": {
    "event": "submit",
    "selector": "#termForm"
  },
  "actions": [
    { "kind": "basher.parseCommand", "field": "#termInput" },
    { "kind": "agent.dispatch", "agent": "mx2cline" }
  ]
}
6. State, Flash-RAM, and Snapshots

State nodes declare the canonical shape of tape or OS state. 

{
  "type": "state",
  "id": "prime.state",
  "value": {
    "user": { "score": 100, "name": "Ranger" },
    "system": { "theme": "dark", "activeTape": "prime-docs" }
  }
}

Flash-RAM nodes store full snapshots for instant boot/restore: 

{
  "type": "flashram",
  "id": "prime.snapshot.001",
  "snapshot": {
    "user.score": 145,
    "system.theme": "grid",
    "system.activeTape": "risk-battlemode"
  }
}
7. Routing, Components, and Layout
7.1 Routes
{
  "type": "route",
  "path": "/",
  "component": "prime.docs.layout",
  "props": {
    "title": "XJSON v1 Manual"
  }
}
7.2 Components
{
  "type": "component",
  "id": "prime.docs.layout",
  "slots": ["sidebar", "content"],
  "template": [
    {
      "type": "element",
      "tag": "div",
      "props": { "scx": "⟁MAIN" },
      "children": [
        { "type": "slot", "name": "sidebar" },
        { "type": "slot", "name": "content" }
      ]
    }
  ]
}
8. Agents & MX2 Family

XJSON expresses agents as structured capability objects, not just URLs. 

{
  "type": "agent",
  "id": "mx2lm",
  "role": "coordinator",
  "skills": ["routing","intent-mapping","memory"],
  "endpoints": {
    "infer": "/api/mx2lm/infer",
    "learn": "/api/mx2lm/learn"
  }
}
9. Tapes, Holotapes, and OS Integration
{
  "type": "tape",
  "id": "xjson-spec-tape",
  "entry": "ui.xjson",
  "publicPath": "/tapes/xjson-spec/public/",

10. Code→AST→XJSON Transformations

XJSON can be produced by reading any source language into an AST, then mapping that AST to the XJSON schema. For example: 


<button id="buy" class="primary">Buy</button>


{
  "type": "element",
  "tag": "button",
  "props": { "id": "buy", "class": "primary" },
  "children": [ { "type": "text", "value": "Buy" } ]
}
11. Security, Trust, and Validation

XJSON supports tape signing, SCX dictionary validation, and agent sandboxing. Because logic is represented structurally, dangerous patterns can be detected before execution.

12. Block Recipes & CDN-fed Block Packs

You can ship block definitions via CDN and use a small JSON form to control variables like spacing, radius, colors, and layout. The runtime merges the incoming variables into the SCX token set. 

{
  "type": "style",
  "id": "cdn.prime.blocks",
  "src": "https://cdn.example.com/xjson/prime-blocks.json",
  "vars": {
    "spacing.base": "10px",
    "radius.card": "12px",
    "color.accent": "#00ffff"
  }
}

This makes it trivial to spin up multiple frontends and OS views, all backed by the same XJSON core with just a different block pack.

13. Reference Grammar (v1)
xjson-document  = object
object          = "{" members "}"
members         = pair *( "," pair )
pair            = string ":" value

value           = string / number / object / array / true / false / null
array           = "[" [ value *( "," value ) ] "]"

node            = element-node
                / style-node
                / logic-node
                / route-node
                / state-node
                / agent-node
                / tape-node
                / flashram-node

element-node    = object with "type" = "element"
style-node      = object with "type" = "style"
logic-node      = object with "type" = "logic"
route-node      = object with "type" = "route"
state-node      = object with "type" = "state"
agent-node      = object with "type" = "agent"
tape-node       = object with "type" = "tape"
flashram-node   = object with "type" = "flashram"
