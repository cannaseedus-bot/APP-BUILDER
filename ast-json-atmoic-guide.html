1 · Core Fusion Laws

1.1 ASX–AST Equivalence Principle

The ASX–AST Fusion Spec v1.0 starts from a single law:

LAW 1 — ASX is an AST-native OS.
Every part of ASX is an AST:

  • index.html → AST of visual layout & UI tree
  • manifest.json → AST of OS law, folds, tapes, routes
  • sw.khl → AST of execution rules & opcodes

3 · AST Execution Pipeline

3.1 DOM → REST → INFER → EXEC → UI

The ASX runtime is an AST pipeline. Each phase is a structured tree transform:

  1. DOM Input AST — user actions turned into a small AST
  2. REST AST — API call as an AST node
  3. Inference AST — MX2LM call as a prompt/response AST
  4. Exec AST — K’uhul opcodes manipulate OS trees
  5. UI AST — Emerald Ghost renders updated DOM

3.3 Execution Law

LAW 3 — Every step is reversible as an AST.

  • No hidden side-effects outside AST transforms
  • Every action can be logged as a tree diff
  • SCXQ2 compresses the AST, not arbitrary bytes
  • Emerald renders AST nodes, not ad-hoc DOM mutations

This makes the entire OS:

  • Replayable
  • Diff-able
  • Compressible
  • Trainable (MX2LM can “think” on AST traces)

4.2 Horizontal Folds = Parallel AST Lanes

Horizontal folds are parallel AST lanes—each fold processes a subtree:

  • Fold 0 — coordinator / meta-AST
  • Fold 1 — runtime orchestration trees
  • Fold 2 — emerald UI component trees
  • Fold 3 — SCXQ2 compression trees
  • Fold 4 — TES/DOOM world trees
  • Fold 5–7 — free lanes for future domains
K’UHUL · FOLD DISTRIBUTOR AST
⟁Wo⟁ fn.horizontal_fold.distribute := (job) -> plan
  ⟁Sek⟁ folds := 8
  ⟁Sek⟁ capacity := fn.get_fold_capacities()

  ⟁Wo⟁ if job.domain == "compression_optimization"
    ⟁Sek⟁ f := 3
  ⟁Wo⟁ else if job.domain == "ui_design_emerald"
    ⟁Sek⟁ f := 2
  ⟁Wo⟁ else if job.domain == "tes_doom_rules_quantum"
    ⟁Sek⟁ f := 4
  ⟁Wo⟁ else
    ⟁Sek⟁ f := fn.load_balance(capacity)

  ⟁Sek⟁ brains := fn.select_brains_for_fold(f, job)
  ⟁Wo⟁ return { "fold": f, "brains": brains, "capacity": capacity[f] }
5 · SCXQ2 as AST Codec

5.1 Trees In, Crystals Out

SCXQ2 is defined as a structural codec for ASTs. It never compresses raw chaos—it compresses patterns in trees:

  • Find repeated glyph patterns in AST nodes
  • Match them against template trees (T_GAME_WORLD, T_STUDIO_UI…)
  • Encode tree parameters into a compact emerald glyph string
  • Optionally entangle similar templates (quantum superposition)

5.2 Compression Pipeline as AST Transform

K’UHUL · SCXQ2 PIPELINE
⟁Wo⟁ fn.scxq2.compress_tape := (tape_ast) -> compressed
  ⟁Sek⟁ glyph_analysis := fn.scxq2.extract_glyphs(tape_ast)
  ⟁Sek⟁ template_match := fn.scxq2.match_template(glyph_analysis)
  ⟁Sek⟁ compressed_ast := fn.scxq2.quantum_compress(tape_ast, template_match)
  ⟁Sek⟁ encoded_str := fn.scxq2.emerald_encode(compressed_ast)

  ⟁Wo⟁ return {
    "compressed": encoded_str,
    "metadata": {
      "compression_ratio": fn.ratio(encoded_str, tape_ast),
      "template_used": template_match.template.id,
      "glyph_pattern": glyph_analysis.patterns.slice(0, 3)
    }
  }

LAW 4 — SCXQ2 is an AST-aware codec.
Compression views trees as symbolic geometry, not just bytes.

8 · Implementation Checklist

8.1 Making an ASX Build “AST-Fused”

To mark a build as compliant with ASX–AST Fusion Spec v1.0, verify these steps:

  • Manifest declares AST context "@ast": "ASX_OS_TREE" at top-level.
  • All major subsystems are trees Folds, agents, builders, tapes, routes all live in XJSON.
  • sw.khl only manipulates ASTs No raw string hacks—always build, transform, or route trees.
  • SCXQ2 wraps AST structures Templates target structured AST, not arbitrary blobs.
  • Emerald Ghost consumes UI_AST UI definitions live as structured JSON, not ad-hoc DOM patches.
  • Horizontal folds are explicit Jobs contain a horizontal_fold and brain_assigned list.
FUSION SEAL

ASX–AST Fusion v1.0 is satisfied when:
every behavior of the OS can be captured as an AST trace, compressed via SCXQ2, replayed by K’uhul, and visualized by Emerald Ghost—without leaving the three-file boundary.
